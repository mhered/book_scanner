# Book Scanner

Book Scanner is a self-hosted tool for cataloguing a physical book collection. Scan a batch of book barcodes with your phone, choose the location where the books are stored, and save the batch with its scan date.

Each imported entry records ISBN, scan date, and location, making it easier to keep track of books stored across shelves, boxes, rooms or even lent to friends. The service is designed for quick mobile use and can be accessed securely from your phone over [Tailscale](https://tailscale.com/).

Typical workflow:
- Scan books with [QR 2 CSV](https://apps.apple.com/us/app/qr-2-csv/id1057463767).
- Share the scan with the `Upload ISBN Scan` shortcut.
- Select a location from the drop-down menu or create a new one.
- Save the import.

## How book records are stored

The server receives a CSV file that must contain comma-separated `Data` and `Timestamp` columns, compatible with the output files generated by `QR 2 CSV`. The supported format for timestamps is `MM/DD/YYYY HH:MM[:SS]`, for example:

```
Data,Timestamp
"9788476724651","10/17/2026 11:26:29"
"9788408031215","10/17/2026 11:26:26"
```

The tree of storage locations is saved in `locations.json`, a human-editable JSON file containing each location's unique `id`, a display `name`, and a `parent_id` that refers to another location in the tree. The required `books` location is the root, and the required `unknown` location must have a valid parent.

```json
{
  "schema_version": 1,
  "locations": [
    { "id": "books", "name": "Books", "parent_id": null },
    { "id": "living-room", "name": "Living room", "parent_id": "books" },
    { "id": "living-room-shelf-a", "name": "Shelf A", "parent_id": "living-room" },
    { "id": "unknown", "name": "Unknown", "parent_id": "books" }
  ]
}
```

The tool stores saved book records in `isbn_list.json`. Each entry is keyed by ISBN, contains a `location_id` that references a location defined in `locations.json` and the book’s most recent `scanned_at` timestamp in ISO 8601 format:

```json
{
  "schema_version": 1,
  "books": {
    "9780140449136": {
      "location_id": "living-room-shelf-a",
      "scanned_at": "2026-10-24T18:42:00"
    },
    "9780261103573": {
      "location_id": "unknown",
      "scanned_at": null
    }
  }
}
```
A `null` timestamp represents an unknown or invalid scan date.

For every confirmed upload, the server shows a summary page:
- **New ISBNs added:** ISBNs that were not already stored.
- **ISBNs updated:** ISBNs whose uploaded timestamp is newer than the stored timestamp, including any ISBN whose stored timestamp is unknown, or whose timestamp is the same but the selected location is different.
- **Already up to date:** ISBNs whose uploaded timestamp is older, whose timestamp and location are unchanged, or whose incoming timestamp is unknown.

To correct a location selected by mistake, upload the batch again and select the correct location. A matching valid timestamp allows the location to change; a strictly older timestamp cannot overwrite the stored timestamp or location. Missing or invalid timestamps do not overwrite existing records.

Missing or malformed timestamps are saved as an unknown timestamp and can be replaced by any later valid timestamp. Rows without an ISBN are skipped and shown in the result. If an ISBN appears more than once in one CSV, its newest valid timestamp is used.

## Configuration

Deployment-specific settings are in `.env`. Copy `.env.example` to `.env` with `cp .env.example .env` and set your custom values:


```
# Network address Uvicorn listens on, e.g. 0.0.0.0
BOOK_SCANNER_BIND_HOST=0.0.0.0
# Local API port for the Book Scanner service
BOOK_SCANNER_PORT=8082
# Public URL used to access the server
BOOK_SCANNER_PUBLIC_URL=http://<server-tailnet-ip>:<port>
```

## Set up the service

You need:

- a home server that stays on while you scan books;
- an iPhone and home server on the same Tailscale network; and
- a Tailscale account.

### 1. Install and connect Tailscale

1. Install Tailscale on the home server using the [official installation instructions](https://tailscale.com/download).
2. Sign in to Tailscale and approve the server in the Tailscale admin console if your tailnet requires approval.
3. Configure Tailscale to start automatically after a server restart:

   ```bash
   sudo systemctl enable --now tailscaled
   ```

4. Run `tailscale status` to confirm the server is connected, then record its Tailscale IPv4 address:

   ```bash
   tailscale ip -4
   ```

5. Install Tailscale on your phone, sign in to the same tailnet, and turn it on. In the Tailscale app, open the account menu and enable **VPN On Demand**. This restores the private connection after an iPhone restart, app update, or temporary network interruption.

Keep Tailscale enabled on the phone. The book-scanner Shortcut uses the private Tailscale address directly; it cannot reliably connect the VPN itself.

### 2. Configure and run the home server

Place the project at `$HOME/apps/book_scanner`, then create the local virtual environment and install the declared dependencies:

```bash
cd "$HOME/apps/book_scanner"
uv sync
set -a
. ./.env
set +a
uv run uvicorn main:app --host "$BOOK_SCANNER_BIND_HOST" --port "$BOOK_SCANNER_PORT"
```

Set `BOOK_SCANNER_PUBLIC_URL` to the address the phone will use, for example:

```text
http://100.106.249.52:8082
```

Verify that the phone can open `$BOOK_SCANNER_PUBLIC_URL/assign-location` while Tailscale is connected. It will show “No uploaded scan batch is waiting” until the first CSV upload.

### 3. Run at startup with systemd

The included service is a **per-user systemd service**: it runs as the account that installs it, starts at boot, and restarts after a failure. It uses systemd's `%h` specifier for that account's home directory, so it expects the project at `$HOME/apps/book_scanner`. Stop any manually started Uvicorn process before enabling it, otherwise the configured port will already be in use.

Install and start the service:

```bash
cd "$HOME/apps/book_scanner"
install -D -m 0644 systemd/book-scanner.service \
  "$HOME/.config/systemd/user/book-scanner.service"
systemctl --user daemon-reload
systemctl --user enable --now book-scanner.service
sudo loginctl enable-linger "$USER"
```

`loginctl enable-linger` keeps the user service running after logout and lets it start at boot. Check that it is active:

```bash
systemctl --user status book-scanner.service --no-pager
. ./.env
batch_url="$(curl --fail-with-body --silent --show-error \
  "http://127.0.0.1:${BOOK_SCANNER_PORT}/upload" \
  --request POST \
  --header 'Content-Type: text/csv' \
  --data-binary @/path/to/QR2CSV.csv)"
printf '%s\n' "$batch_url"
```

Open the returned URL in a browser to select or create the batch location.

To view its logs:

```bash
journalctl --user --unit book-scanner.service --follow
```

After changing [main.py](main.py), restart it:

```bash
systemctl --user restart book-scanner.service
```

The service is reachable from another device on your tailnet at:

```text
$BOOK_SCANNER_PUBLIC_URL/upload
```

Optionally, configure Tailscale Serve to use an HTTPS hostname instead:

```bash
. ./.env
tailscale serve --https=443 "http://127.0.0.1:${BOOK_SCANNER_PORT}"
```

## Testing from another Tailscale device

On another device in the tailnet, upload a CSV and open the returned location-assignment page in the default browser:

```bash
batch_url="$(curl --fail-with-body --silent --show-error \
  --request POST 'http://<server-tailnet-ip>:<port>/upload' \
  --header 'Content-Type: text/csv' \
  --data-binary @'/path/to/csv')"
xdg-open "$batch_url"
```

## iPhone Shortcut

Import the [Upload ISBN Scans shortcut](https://www.icloud.com/shortcuts/576e659b445d42f6be9efc22f319f195). During import, it prompts for the Book Scanner upload URL.

### Create a shortcut manually

The shortcut needs only two actions: one to upload the CSV and one to open the location-assignment URL returned by the server.

#### 1. Connect Tailscale

Open **Tailscale** on the iPhone and make sure it is connected. Keep it connected throughout the upload and location-assignment steps. Note the Tailscale URL used to access the server.

#### 2. Create the shortcut

1. Open **Shortcuts** and tap **+**.
2. Name the shortcut **Upload ISBN Scans**.
3. Open the shortcut's **Details** and enable **Show in Share Sheet**.
4. If there is an **Accepted Types** or **Receive** setting, choose **Files** if available; otherwise leave the default input setting.

#### 3. Add the upload action

1. Tap **Add Action**, search for **Get Contents of URL**, and add it.
2. Enter the upload URL, e.g.:

   ```text
   http://100.106.249.52:8082/upload
   ```

   On another deployment, use `BOOK_SCANNER_PUBLIC_URL` followed by `/upload`.
   The current direct server uses **HTTP, not HTTPS**. Use HTTPS only if you have configured Tailscale Serve or another HTTPS endpoint.

3. If you plan to share the shortcut, add an import question instead of sharing your own server address:
   1. Open the shortcut's details and choose **Setup**.
   2. Tap **Add New Question** and select the upload URL in the **Get Contents of URL** action.
   3. Set the question to **What is your Book Scanner upload URL?**
   4. Optionally set a generic default such as `http://your-server:<port>/upload`. Do not use your own Tailscale address.
   5. Tap **Done** to save the question and **Done** again to save the shortcut.

   When another person imports the shared shortcut, Shortcuts prompts them for their own upload URL.
4. Expand the action using its arrow or **Show More** control.
5. Change **Method** from `GET` to **POST**.
6. Under **Headers**, tap **Add new header** and enter:

   | Field | Value |
   |---|---|
   | Key | `Content-Type` |
   | Value | `text/csv` |

7. Set **Request Body** to **File**, not JSON or Form.
8. Tap the **File** input, choose **Select Variable**, and select **Shortcut Input**.

The action should look like this:

```text
Get Contents of URL
  URL: http://100.106.249.52:8082/upload
  Method: POST
  Headers:
    Content-Type: text/csv
  Request Body: File
  File: Shortcut Input
```

#### 4. Add the browser-opening action

1. Below the upload action, tap **Add Action**.
2. Search for **Open URLs** and add it.
3. Tap its URL input and choose **Select Variable**.
4. Select the **Contents of URL** output belonging to the POST upload action.

**Contents of URL** here is an output variable, not another action to add. Do **not** add a second **Get Contents of URL** action: that downloads the location page as HTML instead of opening it in Safari. Do not select **Shortcut Input** as the input to **Open URLs**.

Remove any extra **Get Contents of URL** or **Show Content** actions. The complete shortcut should contain:

```text
Shortcut Input (CSV file)
  -> Get Contents of URL (POST /upload, File: Shortcut Input)
  -> Open URLs (output of the POST action)
```

#### 5. Upload and save a batch

1. Export your scans as a CSV from **QR 2 CSV**.
2. Tap **Share** on the exported CSV file.
3. Choose **Upload ISBN Scans**.
4. Allow network or browser permissions if prompted.
5. Safari should open a page titled **Assign a location**.
6. Select an existing location or create one.
7. Tap **Assign location and save**.

Uploading holds one scan batch in memory. Uploading another CSV replaces the waiting batch, and restarting the service discards it. Only **Assign location and save** writes the book records to `isbn_list.json`. The result page lists added, updated, and already up-to-date ISBNs. Upload the CSV again if the waiting batch was replaced or the service restarted.

### Troubleshooting an invalid URL

If **Open URLs** reports "Make sure you pass a valid URL":

1. Temporarily insert **Show Result** immediately after the POST action.
2. Set its input to the POST action's **Contents of URL** output.
3. Run the shortcut with a CSV file and inspect the result. It should be a single URL like:

   ```text
   http://100.106.249.52:8082/assign-location
   ```

4. If it shows HTML beginning with `<!doctype html>`, remove any second **Get Contents of URL** action. If the POST itself returned HTML, read the error message in that response.
5. If it shows CSV content, you selected **Shortcut Input** instead of the POST action's output.
6. Remove **Show Result** after checking. Explicitly set **Open URLs** back to the POST action's **Contents of URL** output, not the temporary **Show Result** action's output.
